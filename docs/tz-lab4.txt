ТЗ на систему Dendro Age
Скопировать в Word как Приложение 1 к РПЗ. Нумерация внутри пунктов сплошная.

1. Цель
1.1. Веб-сервис для просмотра и публикации аномальных паттернов дендрошкалы: год начала события и число колец.

2. Назначение
2.1. Сервис хранит карточки паттернов, фото и видео, ленту и плитку.
2.2. Гость читает опубликованные паттерны.
2.3. Создатель регистрируется, входит по JWT и ведёт свой черновик: создаёт, публикует, удаляет и ставит лайк.

3. Задачи
3.1. Страницы ленты, плитки и добавления на сервере. Go, Gin, HTML-шаблоны, CSS.
3.2. База и файлы. PostgreSQL 16, GORM, Adminer, MinIO.
3.3. REST API карточек и исследователей. Go, Gin, префикс /api.
3.4. Аутентификация и авторизация создателя. JWT HS256, Redis blacklist, Swagger.
3.5. SPA гостя: лента и плитка на mock-данных. React, TypeScript, React-Bootstrap.
3.6. SPA с живым API, лайками и добавлением. React, Redux Toolkit, axios, код из Swagger.
3.7. Завершение фронтенда создателя и гостя поверх того же API.
3.8. Демонстрация страниц через GitHub Pages.
3.9. Документация: ER, диаграмма классов, диаграмма последовательности, ТЗ, РПЗ. StarUML, Word.
3.10. Репозиторий Git с веткой по теме. GitHub.

4. Функциональные требования
4.1. HTTP-методы
4.1.1. GET /api/dendro_scale_patterns?date_from=&date_to= — список опубликованных. Гость и создатель.
4.1.2. GET /api/dendro_scale_patterns/feed — лента без id. Гость и создатель.
4.1.3. GET /api/dendro_scale_patterns/feed/:id?next=true — лента по id или следующий. Гость и создатель.
4.1.4. POST /api/dendro_researchers/register — регистрация. Гость.
4.1.5. POST /api/dendro_researchers/login — аутентификация, ответ access_token. Гость.
4.1.6. POST /api/dendro_scale_patterns — черновик с фото и видео. Только создатель, creator_id из JWT.
4.1.7. GET /api/dendro_scale_patterns/draft — черновик текущего создателя. Только создатель.
4.1.8. PUT /api/dendro_scale_patterns/publish — публикация. Только создатель. Гость получает 401.
4.1.9. DELETE /api/dendro_scale_patterns/:id — логическое удаление. Только создатель.
4.1.10. POST /api/dendro_scale_patterns/:id/like — лайк 1 или 0. Только создатель.
4.1.11. POST /api/dendro_researchers/logout — токен в Redis blacklist. Только создатель. Повтор с тем же токеном — 403.

4.2. Меню
4.2.1. HTML: лента, добавление, плитка.
4.2.2. Будущее SPA: лента, добавление, плитка, вход. Гостю доступны лента и плитка.

4.3. Аутентификация
4.3.1. Гость вводит логин и пароль, вызывается POST login.
4.3.2. Создатель передаёт Authorization: Bearer и вызывает методы черновика, публикации, удаления, лайка и выхода.

4.4. Плитка
4.4.1. Гость и создатель открывают список и фильтр по календарным датам. Вызывается GET списка.
4.4.2. Создатель удаляет карточку. Вызывается DELETE.

4.5. Лента
4.5.1. Гость и создатель листают карточки. Вызываются GET ленты без id и GET ленты с next=true.
4.5.2. Создатель ставит или снимает лайк. Вызывается POST like.

4.6. Добавление
4.6.1. Создатель указывает название, фото и видео и нажимает «Далее». Вызывается POST создания.
4.6.2. Страница черновика читает GET draft.
4.6.3. Создатель заполняет краткое описание, год начала и число колец и публикует. Вызывается PUT publish.

5. Требования к аппаратному обеспечению
5.1. Сервер: 2 ядра, 4 ГБ ОЗУ, 20 ГБ диска под PostgreSQL, MinIO и Redis.
5.2. Клиент: 2 ядра, 4 ГБ ОЗУ, браузер, экран от 360 px по ширине.

6. Требования к программному обеспечению
6.1. Сервер: Windows 10/11 или Ubuntu 22.04, Go 1.26, Gin 1.12, PostgreSQL 16, Redis 7, MinIO, Docker Desktop.
6.2. Клиент: Chrome или Edge, Postman или Insomnia, Swagger UI по адресу /swagger.
