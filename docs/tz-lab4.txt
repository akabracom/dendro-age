Заголовки разделов: тёмная заливка #1C1C1C, шрифт белый, Times New Roman 14,
межстрочный 1,5, поля слева 30 мм, справа 15 мм, сверху и снизу 20 мм.


1. Цель

1.1. Разработать веб-сервис на Go и клиентские страницы, которые позволяют
     учитывать аномальные паттерны дендрошкалы (год начала события и число
     колец), публиковать карточки, просматривать ленту и плитку.

Система состоит из двух компонентов:
  — серверная часть: Go, Gin, PostgreSQL, MinIO, Redis, JWT;
  — клиентская часть: браузер, HTML-страницы, далее SPA на React.


2. Назначение

Dendro Age предназначен для накопления и просмотра сведений об аномальных
паттернах дендрошкалы, необходимых для оценки возраста находки.
В системе работают две группы пользователей.

2.1. Гость — просматривает плитку опубликованных паттернов с фильтром
     по календарным датам и ленту с видео, может зарегистрироваться и войти.

2.2. Создатель (авторизованный исследователь) — дополнительно создаёт
     черновик с фото и видео, публикует карточку, удаляет свои записи
     и ставит лайки.


3. Задачи

Формат: номер, что сделать одним предложением, технологии в конце строки.

3.1. Разработка дизайна трёх страниц («Лента», «Добавление», «Плитка»)
     в портретном мобильном формате и серверной шаблонизации.
     Технологии: HTML, CSS, Go, Gin, MinIO, Docker.
3.2. Разработка структуры базы данных и подключение к бэкенду, логическое
     удаление паттерна через смену статуса. Технологии: PostgreSQL, Adminer, GORM, Docker Compose.
3.3. Создание веб-сервиса REST API на десять методов домена паттерна
     и исследователя. Технологии: Go, Gin, /api, Postman.
3.4. Реализация аутентификации и авторизации, хранение отозванных токенов,
     документирование API. Технологии: JWT HS256, Redis (blacklist), Swagger.
3.5. Разработка базового SPA для гостя: «Лента» и «Плитка» на mock-данных.
     Технологии: React, TypeScript, Vite, React-Bootstrap.
3.6. Завершение интерфейса создателя: вход, создание и публикация, удаление, лайки.
     Технологии: Redux Toolkit, axios, код из Swagger.
3.7. Завершение фронтенда гостя и создателя поверх того же API.
     Технологии: React, JWT в браузере, axios.
3.8. Развёртывание демо-версии фронтенда. Технологии: GitHub Pages, HTTPS.
3.9. Подготовка документации: РПЗ, ТЗ, ER, классы, последовательность.
     Технологии: Microsoft Word, StarUML.
3.10. Оформление репозиториев бэкенда и фронтенда с веткой по теме и README.
      Технологии: Git, GitHub.


4. Функциональные требования

4.1. Методы HTTP

4.1.1. GET получение списка опубликованных паттернов с фильтром date_from и date_to. Признак mine 0/1.
4.1.2. GET получение ленты без идентификатора. Признак liked 0/1.
4.1.3. GET получение ленты по идентификатору или следующей карточки (next=true).
4.1.4. GET получение черновика текущего создателя (ид в адресе нет).
4.1.5. POST создание черновика с фото и видео в MinIO.
4.1.6. PUT публикация черновика (статус published).
4.1.7. DELETE логическое удаление своей карточки.
4.1.8. POST постановка или снятие лайка (like 1 или 0).
4.1.9. POST регистрация исследователя.
4.1.10. POST аутентификация, выдача JWT.
4.1.11. POST выход, токен в blacklist Redis.

4.2. Меню
4.2.1. HTML: лента, добавление, плитка. Панель внизу.
4.2.2. SPA: лента, добавление, плитка, вход. Гостю доступны лента и плитка.
4.2.2.1. Лента — требования 4.5.
4.2.2.2. Добавление — требования 4.6.
4.2.2.3. Плитка — требования 4.4.
4.2.2.4. Вход — требования 4.3.
4.2.2.5. Выход создателя — метод 4.1.11.

4.3. Аутентификация
4.3.1. Доступна гостю.
4.3.2. Поля: логин, пароль.
4.3.3. Войти — метод 4.1.10. Зарегистрироваться — метод 4.1.9.

4.4. Плитка
4.4.1. Гость и создатель.
4.4.2. Карточки опубликованных паттернов (метод 4.1.1): фото, название, год, кольца, число лайков.
4.4.3. Пустой URL заменяется файлом из static, не из MinIO.
4.4.4. Фильтр календарём. Удаление своей карточки — метод 4.1.7.

4.5. Лента
4.5.1. Гость и создатель.
4.5.2. Одна карточка: видео, название, описание, год, кольца, like_count и liked 0/1.
4.5.3. Следующая — метод 4.1.3. Лайк — метод 4.1.8.

4.6. Добавление
4.6.1. Только создатель.
4.6.2. Шаг 1: название, фото, видео, «Далее» — метод 4.1.5.
4.6.3. Шаг 2: черновик методом 4.1.4, описание, год, кольца, «Опубликовать» — метод 4.1.6.


5. Требования к аппаратному обеспечению

5.1. Сервер: 1 ядро от 2 ГГц, 4 ГБ ОЗУ, 20 ГБ SSD, сеть 100 Мбит/с.
5.2. Клиент: 2 ядра, 2 ГБ ОЗУ, экран от 360 px, доступ в сеть.


6. Требования к программному обеспечению

6.1. Сервер: Windows 10/11 или Ubuntu 22.04; Go 1.26; Gin; PostgreSQL 16; Redis 7; MinIO; Docker.
6.2. Клиент: Chrome или Edge; Postman; Swagger UI по адресу /swagger.
