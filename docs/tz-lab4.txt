ТЗ — скопировать в Word как Приложение 1 к РПЗ
================================================
Титульный лист ТЗ — отдельный, НЕ титульник РПЗ.
На титуле ТЗ: «Техническое задание» / наименование системы Dendro Age /
студент / группа ИУ5-51Б / 2026.
Титульник РПЗ — кафедра, «Расчётно-пояснительная записка», тема ВКР/РПЗ.
Не подставляй титул ТЗ вместо титула РПЗ.

Нумерация внутри пунктов сплошная: 1.1, 2.1, 3.1 … 3.10, 4.1 …


1. Цель

1.1. Разработать веб-сервис учёта аномальных паттернов дендрошкалы
     (год начала события и число колец) с публикацией карточек,
     лентой и плиткой.

Система состоит из двух компонентов:
  — серверная часть: Go, Gin, PostgreSQL, MinIO, Redis, JWT, HTML-страницы;
  — клиентская часть: браузер, позже SPA на React.


2. Назначение

2.1. Dendro Age предназначен для исследователя дендрошкалы, который
     просматривает опубликованные паттерны в ленте и плитке, создаёт
     черновик с фото и видео, публикует карточку с годом начала и числом
     колец, ставит лайк и логически удаляет свои записи; гость читает
     те же опубликованные карточки без входа.


3. Задачи

Формат каждой задачи: номер, что сделать, технологии в конце той же строки.

3.1. Лабораторная 1. Три HTML-страницы: лента, плитка, добавление. Go, Gin, шаблоны, CSS.
3.2. Лабораторная 2. Три таблицы PostgreSQL, черновик и публикация, MinIO. GORM, Adminer, Docker.
3.3. Лабораторная 3. REST API десяти методов домена паттерна и исследователя. Gin, /api, Postman.
3.4. Лабораторная 4. Аутентификация JWT, blacklist в Redis, Swagger, ТЗ. golang-jwt, Redis 7.
3.5. Лабораторная 5. SPA гостя: лента и плитка на mock. React, TypeScript, React-Bootstrap.
3.6. Лабораторная 6. SPA с живым API, лайки и добавление. Redux Toolkit, axios, код из Swagger.
3.7. Лабораторная 7. Завершение фронтенда гостя и создателя. React, JWT в браузере.
3.8. Демонстрация. Публикация статических страниц. GitHub Pages.
3.9. Документация. ER, классы, последовательность, ТЗ, РПЗ. StarUML, Word.
3.10. Репозиторий. Ветки по теме, README с таблицами и методами. Git, GitHub.


4. Функциональные требования

Шесть подпунктов: HTTP, меню, аутентификация, плитка, лента, добавление.

4.1. HTTP-методы веб-сервиса

4.1.1. GET /api/dendro_scale_patterns — список опубликованных, фильтр date_from и date_to. Гость и создатель. Признак mine 0/1.
4.1.2. GET /api/dendro_scale_patterns/feed — лента без ид. Гость и создатель. Признак liked 0/1.
4.1.3. GET /api/dendro_scale_patterns/feed/:id?next=true — лента по ид или следующая. Гость и создатель.
4.1.4. GET /api/dendro_scale_patterns/draft — черновик текущего создателя, ид в адресе нет. Создатель.
4.1.5. POST /api/dendro_scale_patterns — черновик, файлы фото и видео в MinIO. Создатель.
4.1.6. PUT /api/dendro_scale_patterns/publish — смена статуса на published. Создатель. Гость 401.
4.1.7. DELETE /api/dendro_scale_patterns/:id — soft delete, только свои. Создатель.
4.1.8. POST /api/dendro_scale_patterns/:id/like — like 1 ставит, 0 снимает. Создатель.
4.1.9. POST /api/dendro_researchers/register — регистрация. Гость.
4.1.10. POST /api/dendro_researchers/login — аутентификация, JWT. Гость.
4.1.11. POST /api/dendro_researchers/logout — токен в Redis. Создатель.

4.2. Меню

4.2.1. Три пункта: лента, добавление, плитка. На всех HTML-страницах снизу.
4.2.2. Позже четвёртый пункт «Вход». Гостю доступны лента и плитка.

4.3. Окно аутентификации (гость и создатель)

4.3.1. Гость вводит логин и пароль. Вызов 4.1.10.
4.3.2. Нет учётки — регистрация. Вызов 4.1.9.
4.3.3. Создатель после входа передаёт Authorization: Bearer. Выход — вызов 4.1.11.

4.4. Окно плитки (гость и создатель)

4.4.1. Список опубликованных карточек. Вызов 4.1.1.
4.4.2. Фильтр календарём date_from и date_to. Вызов 4.1.1.
4.4.3. Создатель удаляет свою карточку. Вызов 4.1.7.
4.4.4. Пустые URL заменяются фото и видео с сервера /static/defaults, не из MinIO.

4.5. Окно ленты (гость и создатель)

4.5.1. Первая карточка без ид. Вызов 4.1.2.
4.5.2. Следующая. Вызов 4.1.3 с next=true.
4.5.3. На карточке два числа: like_count и liked 0/1.
4.5.4. Создатель ставит или снимает лайк. Вызов 4.1.8.

4.6. Окно добавления (создатель)

4.6.1. Название, файл фото, файл видео, кнопка Далее. Вызов 4.1.5.
4.6.2. Страница читает черновик. Вызов 4.1.4.
4.6.3. Краткое описание, год начала, число колец, Опубликовать. Вызов 4.1.6.


5. Требования к аппаратному обеспечению

5.1. Сервер: 2 ядра, 4 ГБ ОЗУ, 20 ГБ SSD.
5.2. Клиент: 2 ядра, 4 ГБ ОЗУ, экран от 360 px.


6. Требования к программному обеспечению

6.1. Сервер: Windows 10/11 или Ubuntu 22.04; Go 1.26; Gin 1.12; PostgreSQL 16; Redis 7; MinIO; Docker Desktop.
6.2. Клиент: Chrome или Edge; Postman; Swagger UI по адресу /swagger.
