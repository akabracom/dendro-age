Диаграмма последовательности Dendro Age
=======================================
Масштаб: три колонки на А4, шрифт 10–11 pt. Не пиши полный URL
в две строки на каждой стрелке — ломай имя Message Enter'ом.

Линии жизни — КОРОТКИЕ имена, с переносом внутри бокса:
  Postman
  :Researchers
  :Patterns
В type/classifier всё равно классы Домен DendroResearchers
и Домен DendroScalePatterns с диаграммы классов.

На стрелке только хвост пути + скобки:
  login(login, password)
  list(date_from, date_to)
  create(title, image, video)
  draft()
  publish(short, year, rings)
  feed()
  feed(id, next=true)
  like(id, like)
Ответ: JWT / JSON. Не копируй /api/dendro_scale_patterns целиком.

Сплошные туда, пунктир обратно, номера 1…16.
Без БД, без Redis, без MinIO.

================================================================
ТРИ ОБЪЕКТА (Lifeline) — слева направо
================================================================

Это не таблицы и не модели. Это те же домены, что на
диаграмме классов.

1) Слева — клиент
   Имя: Postman
   Подпись в скобках: (создатель)
   В примере у одногруппника это «Фронтенд (создатель)».
   У тебя клиент на диаграмме классов — Postman, поэтому так и пиши.
   В StarUML: Toolbox → Sequence → Lifeline.
   В свойствах stereotype можно не ставить.
   Role / name: Postman
   Если хочешь как в примере — имя «Фронтенд», в скобках «создатель».

2) Середина — домен пользователей
   Имя: : Домен DendroResearchers
   Двоеточие в начале как в примере («: Домен users») —
   это безымянный экземпляр класса.
   В StarUML: Lifeline, поле type / classifier укажи класс
   «Домен DendroResearchers» с диаграммы классов
   (если класс уже есть в модели — перетащи его на sequence,
   StarUML сам сделает :ИмяКласса).

3) Справа — домен паттернов
   Имя: : Домен DendroScalePatterns
   Classifier = класс «Домен DendroScalePatterns» с диаграммы классов.


Не добавляй:
  PostgreSQL, Redis, MinIO, Handler, Repository, JWT как отдельный
  столбец, страницы FeedPage/MosaicPage.


================================================================
КАКИЕ ЛИНИИ
================================================================

Вертикальные серые пунктиры вниз от каждого объекта —
это линии жизни. Их StarUML рисует сам, не рисуй руками.

Горизонтальные сообщения — два вида:

А) Запрос (нечётные 1, 3, 5, 7, 9, 11, 13, 15)
   Toolbox → Sequence → Message (или Synchronous Message).
   Стрелка СПЛОШНАЯ, наконечник закрытый.
   messageSort = synchCall
   Идёт СЛЕВА НАПРАВО: от Postman к нужному домену.
   На домене появляется узкий столбик Activation —
   оставь его, как на примере.

Б) Ответ (чётные 2, 4, 6, 8, 10, 12, 14, 16)
   Toolbox → Sequence → Reply Message
   (или обычный Message, в свойствах messageSort = reply).
   Стрелка ПУНКТИРНАЯ, наконечник открытый.
   Идёт СПРАВА НАЛЕВО: от домена обратно к Postman.
   Текст короткий: JWT или JSON …

Не ставь стрелки между двумя доменами.
Не ставь петли на себя.
Не подписывай линии словами «Dependency» / «Usage» —
это не диаграмма классов.


================================================================
SIGNATURE И ARGUMENTS (это смотрят на скрине 9)
================================================================

Преподаватель: signature сообщения = метод с диаграммы классов.
arguments — вход и выход в скобках у Message.

Как заполнять одно сообщение в StarUML:

1. Кликни стрелку.
2. Поле name / signature — вставь операцию домена
   ТОЧНО как на диаграмме классов, с глаголом HTTP.
3. Поле arguments — то, что в скобках на примере.

Не выдумывай короткие имена login() / list(), если на классах
написан полный путь /api/....

================================================================
ШАГИ В STARUML
================================================================

1. Открой ТОТ ЖЕ файл .mdj, где ER и классы.
2. Model Explorer → правый клик по модели → Add Diagram →
   Sequence Diagram.
3. Имя диаграммы: Диаграмма последовательности.
4. Слева вверху рамка sd появится сама. Подпись:
   «Диаграмма последовательности».
5. Перетащи на холст три Lifeline. Расставь как на примере:
   Postman | DendroResearchers | DendroScalePatterns.
   Домен пользователей уже, домен паттернов шире — как в примере.
6. Чтобы signature брался из классов:
   в Model Explorer найди операции доменов и при создании
   Message в поле signature выбери операцию из списка,
   не печатай путь руками заново.
7. Рисуй парой: запрос → сразу reply под ним.
   Не рисуй все запросы подряд, иначе ответы перепутаются.
8. Если Activation (серый столбик) не появился —
   правый клик по линии жизни домена → Add → Activation,
   высотой ровно на одну пару запрос+ответ.
9. Шрифт 9–10 pt, лист книжный. Стрелки не должны наезжать
   текстом друг на друга: ломай подпись на две строки,
   как в примере с POST /api/particles.


================================================================
ЧТО ПРОВЕРИТЬ ПЕРЕД СКРИНОМ 9
================================================================

- Три колонки, не больше.
- 8 сплошных вправо, 8 пунктиров влево, номера 1–16 по порядку.
- Сообщение 1 и 2 идут в средний столбец (исследователи).
- Сообщения 3–16 идут в правый столбец (паттерны).
- В скобках у создания — title, image, video.
- У публикации — short_description, event_year, ring_count
  (это твои два поля темы + краткое описание).
- У ленты с id — next=true.
- У лайка — like (0 или 1).
- Нет таблиц, нет «HTTP 200» вместо JSON.
- signature совпадает с операциями на диаграмме классов.
