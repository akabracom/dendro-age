# Dendro Age — фронтенд гостя (лаба 5)

SPA на React + TypeScript + Vite + React-Bootstrap. Данные только из mock, бэкенд не нужен. Redux и Context нет.

```bash
cd web
npm install
npm run dev
```

Открой http://localhost:5173 — редирект на ленту. В Network не будет запросов к `/api`, только статика Vite и файлы `/defaults/...`.

## Страницы

Нижняя панель из четырёх пунктов: **Лента**, **Добавить**, **Плитка**, **Вход**. Доступны только лента и плитка. Добавить и Вход серые, без перехода.

### Лента `/feed` и `/feed/:id`

Просмотр одного опубликованного паттерна поверх видео.

Поля: год начала, число колец, `like_count`, `liked` (у гостя всегда 0).

Кнопки: **Следующий** — следующий mock-паттерн.

Если `imageUrl` или `videoUrl` пустые, подставляются `/defaults/pattern_default.svg` и `/defaults/pattern_default.mp4` (лежат в проекте, не MinIO).

### Плитка `/mosaic`

Сетка карточек опубликованных паттернов.

Фильтр (поля темы): календарь **С** (`date_from`), календарь **по** (`date_to`), текст **Название**. Кнопка **Найти**. Сервер не вызывается: год берётся из даты и сравнивается с `eventYear` mock-объекта.

Клик по карточке открывает ленту этого id.

### Добавление `/add` и Вход `/login`

Заглушки «недоступно гостю». Пункты навбара к ним не ведут.

## Компоненты и хуки

- `PatternFilter` — форма фильтра, все значения приходят **props** (`dateFrom`, `dateTo`, `titleQuery` и колбэки). Состояние фильтра живёт в `MosaicPage`.
- `PatternCard` — карточка, props: `pattern`.
- `MosaicPage`: `useState` (список, поля фильтра), `useEffect` (загрузка mock при монтировании).
- `FeedPage`: `useState` (список и индекс), два `useEffect` (загрузка mock; синхронизация индекса с `:id`).

## Расчёт аппаратных требований

Исходные числа (не переменные «N», а данные Dendro Age):

- одновременно работают 50 исследователей;
- рабочий день 8 часов = 28800 секунд;
- один исследователь за день оформляет 10 паттернов;
- на один паттерн 6 HTTP-запросов: GET список, POST создание, GET черновик, PUT публикация, GET лента, POST like.

**RPS**

RPS = 50 × 10 × 6 / 28800 = 3000 / 28800 = **0,104** запроса в секунду.

Пик (80 % нагрузки за 2 часа = 7200 с): RPS_пик = 3000 / 7200 = **0,42**.

**Ядра и ОП** (по правилу курса: на 1 ядро 4 ГБ ОП; одно ядро держит не меньше 1 RPS с запасом):

Ядра = ⌈0,42⌉ = **1 ядро**.  
ОП = 1 × 4 = **4 ГБ**.

**Диск за 5 лет**

Строка `dendro_scale_patterns` в байтах:

| поле | байт |
|---|---|
| id | 8 |
| title VARCHAR(160) | 160 |
| short_description VARCHAR(500) | 500 |
| full_description VARCHAR(2000) | 2000 |
| status VARCHAR(20) | 20 |
| image_url VARCHAR(255) | 255 |
| video_url VARCHAR(255) | 255 |
| event_year | 8 |
| ring_count | 8 |
| created_at | 8 |
| formed_at | 8 |
| creator_id | 8 |
| **итого строка** | **3238** |

Округляем с накладными расходами PostgreSQL до 4096 байт на строку.

Число паттернов за 5 лет = 50 × 10 × 365 × 5 = **912 500**.

Объём таблицы паттернов = 912500 × 4096 = 3 737 600 000 байт ≈ **3,5 ГБ**.

Лайки: в среднем 3 лайка на паттерн, строка like ≈ 24 байта → 912500 × 3 × 24 ≈ **66 МБ**.

Объекты MinIO (S3) на один паттерн: фото 2 МБ + видео 8 МБ = 10 МБ.  
S3 за 5 лет = 912500 × 10 МБ = **8,7 ТБ**.

Итого диск сервера с запасом 20 %: 3,5 ГБ + 0,07 ГБ + 8,7 ТБ ≈ **10,5 ТБ**.

## Расчёт в формате для листа РПЗ

В системе Dendro Age работают 50 исследователей дендрошкалы. Каждый за рабочий день публикует 10 паттернов.

N_(patterns/day) = 50 × 10 = 500 паттернов/сутки	(1)

На каждый паттерн согласно диаграмме последовательности (рисунок 3) приходится 8 HTTP-запросов: POST login, GET список, POST создание с фото и видео, GET черновик, PUT публикация, GET лента, GET лента с next=true, POST like. Рабочий день 8 часов = 28800 с. RPS вычисляется по формуле 2.

RPS = (N_(patterns/day) × 8) / 28800 = (500 × 8) / 28800 = 4000 / 28800 ≈ 0,14 запроса/с	(2)

Количество ядер — формула 3 (k_reserve = 1,5; одно ядро обрабатывает RPS_core = 500). Объём ОП — формула 4: на 1 ядро 4 ГБ.

N_cores = RPS / RPS_core × k_reserve = 0,14 / 500 × 1,5 ≈ 0,0004 → принимаем 1 ядро	(3)

RAM = 4 × N_cores = 4 × 1 = 4 ГБ	(4)

Размер записи таблицы услуг dendro_scale_patterns (ид и создатель — по 8 байт, две системные даты — по 8 байт, название — 160 байт, статус — 20 байт, два URL — по 255 байт, два описания — 500 и 2000 байт, год начала и число колец — по 8 байт) и таблицы лайков dendro_pattern_likes (ид, исследователь и паттерн — по 8 байт) — формулы 5 и 6. На один паттерн в среднем 3 лайка. Объект в MinIO (S3): фото 2 МБ и видео 8 МБ.

S_dsp = 8 + 8 + 8 × 2 + 160 + 20 + 255 × 2 + 500 + 2000 + 8 + 8 = 3238 байт	(5)

S_like = 8 × 3 = 24 байт	(6)

S_s3 = 2 × 1024 × 1024 + 8 × 1024 × 1024 = 10485760 байт ≈ 10 МБ	(7)

Годовой поток паттернов — формула 8. Прирост БД за год — формула 9. Прирост MinIO — формула 10. Диск на 5 лет с запасом N_reserve = 10 ГБ — формула 11.

N_year = N_(patterns/day) × 365 = 500 × 365 = 182500 паттернов/год	(8)

DB_(growth/year) = (N_year × (S_dsp + 3 × S_like)) / (1024 × 1024 × 1024) = (182500 × (3238 + 72)) / (1024³) ≈ 0,56 ГБ/год	(9)

S3_(growth/year) = (N_year × S_s3) / (1024 × 1024 × 1024) = (182500 × 10485760) / (1024³) ≈ 1740 ГБ/год ≈ 1,7 ТБ/год	(10)

Disk_total = 5 × (DB_(growth/year) + S3_(growth/year)) + N_reserve = 5 × (0,56 + 1740) + 10 ≈ 8713 ГБ ≈ 8,5 ТБ	(11)
